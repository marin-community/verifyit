# Issues and comments

Assume the reader knows the repository but was not present for the problem.
State the symptom or requested outcome early. Include the smallest useful
reproduction, expected behavior, and evidence. Keep titles at most 80 characters:
a factual symptom for bugs and an imperative outcome for tasks.

Use plain `Reproduce:`, `Expected:`, or `Done when:` labels when they help.
Link extended logs or investigation history. Do not prescribe an implementation
unless that choice is part of the task. See [file-issue](../file-issue/SKILL.md)
for publication and authorization rules.

Comments explain what changed, the result, and the next action when one exists.
Avoid repeating the issue body. Keep evidence linked and distinguish observed
results from hypotheses. Agent-authored comments start with `🤖`.

Apply [ai-writing-donts.md](ai-writing-donts.md) before publication. Every
sentence should add a symptom, impact, reproduction, observation, expected
behavior, completion criterion, or decision.
