## Package and grading contracts

- Support Python >=3.11. The shared style tooling runs separately on Python >=3.12.
- Keep the core dependency limited to `tomlkit`; isolate optional dependencies
  in mode extras. Do not add a dependency on Marin or its services to verifyit.
- Preserve spec parsing/rendering, public imports, CLI behavior, verdict statuses,
  and reward files described in README.md. Distinguish a candidate scoring zero
  from an invalid task or infrastructure error.
- Maintain process-group cleanup on timeout. For pytest, JUnit, and Go modes,
  restore task-supplied paths from `spec.restore` before setup and execution;
  `must_not_break` IDs protect previously passing tests when scoring.
- Search the existing parsers, graders, and shared execution helpers before adding a helper.

## Repository workflows

The shared skills are generated by `marin-style sync`; do not edit files listed
in `.agents/marin-style/manifest.json`. Put repository-specific guidance here
or in a repository-owned skill. `review-pr`, `fix-issue`, `noslop`, and
`update-docs` remain repository-owned.

Use a `codex/` prefix for agent branches. Never amend or force-push without user
authorization. Publishing a PR does not authorize merging it.

Use heartbeats for PR monitoring where available, rather than the shared
commit skill's foreground watch command. Monitor until merge/closure, a user
stop request, or 12 hours after monitor creation. Stay quiet while state is
unchanged; notify on actionable failures or feedback, decisions, completion,
or timeout. Disable the heartbeat on its terminal condition.

If a headless lint reviewer cannot run, report that limitation, do not claim
a catalog review passed, and use an independent read-only subagent review when
available. Keep normal mechanical checks and self-review mandatory. A missing
reviewer or label-management permission alone does not block authorized publication;
report the limitation instead. Do not merge without explicit user authorization.

Routine implementation and code-debugging notes belong in the active task,
issue, or PR. Use Echo for relevant prior work, requested cross-project records,
and live infrastructure incidents; avoid creating a log for every local debug step.
